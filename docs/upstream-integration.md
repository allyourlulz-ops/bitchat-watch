# Putting the watch bridge into upstream bitchat iOS

The standalone `BitchatWatchHost` app is for development. For real use, the iPhone side of the watch companion
(WatchConnectivity bridge + channel chat over LAN/MPC + the `0x7E` bitchat bridge) goes into the real bitchat
iOS app, so the watch sees the phone's full mesh (relays, history, favourites) instead of a leaf view.

Tested against **permissionlesstech/bitchat `04995f68`** ("Port the Android globe geohash picker to iOS (#1807)").
Other commits may need the anchors in the patch adjusted.

## 1. What the patch does

`upstream-patches/0001-watch-companion-bridge.patch` (generated by `scripts/make-upstream-patch.sh`) is additive
except for five small hooks:

| File | Change |
|------|--------|
| `bitchat/Services/BLE/BLEService.swift` | `opaquePacketObserver` called for unknown packet types (relaying unchanged); `broadcastOpaque(type:payload:ttl:)`, which refuses any core `MessageType` |
| `bitchat/ViewModels/ChatOutgoingCoordinator.swift`, `ChatViewModel.swift` | `sendMeshText(_:)`: send to the mesh public channel whatever channel is active in the UI |
| `bitchat/App/AppRuntime.swift` | creates and starts `BitchatWatchBridgeAdapter` (`#if os(iOS)` only) |
| `bitchat/Info.plist` | `NSLocalNetworkUsageDescription`, `NSBonjourServices` (`_hkchan._tcp`, `_hk-chan._tcp`, `_hk-chan._udp`) |
| **new** `bitchat/WatchBridge/BitchatWatchBridgeAdapter.swift` | maps ChatViewModel / BLEService to the bridge façade |
| **new** `localPackages/WatchBridgeKit/` | Swift package: internal copies of our shared code, one public file (`WatchBridgePublic.swift`) so nothing collides with upstream's own `SecureLogger`, `ConversationID`, etc. |

## 2. Apply it

```sh
git clone https://github.com/permissionlesstech/bitchat.git
cd bitchat
git checkout 04995f68
git apply --check /path/to/bitchat-watch/upstream-patches/0001-watch-companion-bridge.patch
git apply /path/to/bitchat-watch/upstream-patches/0001-watch-companion-bridge.patch
```

If `--check` fails on a newer upstream, regenerate against your checkout (it must be clean):

```sh
/path/to/bitchat-watch/scripts/make-upstream-patch.sh /path/to/bitchat
```

The script asserts every anchor it edits and stops with `anchor not found in …` if upstream moved something.

## 3. Wire it into the checked-in `bitchat.xcodeproj` (by hand)

Upstream checks in its project (no XcodeGen). It uses **file-system synchronized groups** for the `bitchat/`
folder, so the new `bitchat/WatchBridge/BitchatWatchBridgeAdapter.swift` is picked up by `bitchat_iOS` and
`bitchat_macOS` automatically; the file is `#if os(iOS)` so the macOS target ignores it.

What you have to do in Xcode 26:

### 3a. Add the WatchBridgeKit package

1. Open `bitchat.xcodeproj`.
2. *Project ▸ bitchat ▸ Package Dependencies ▸ +* ▸ **Add Local…** ▸ choose `localPackages/WatchBridgeKit`
   (same as the existing `BitFoundation`, `BitLogger`, `Arti` local packages).
3. Add the **WatchBridgeKit** library product to the **bitchat_iOS** target only
   (*Target ▸ General ▸ Frameworks, Libraries, and Embedded Content*). Not to `bitchat_macOS` or the share extension.
4. Build `bitchat_iOS`. The adapter imports `WatchBridgeKit`, `BitFoundation` and `Combine`.

### 3b. Add the watch app target

1. *File ▸ New ▸ Target… ▸ watchOS ▸ App*. Name `bitchatWatch`, interface SwiftUI, **"Watch App for Existing
   iOS App"** with companion `bitchat_iOS`. Xcode creates a single-target watch app with bundle ID
   `<iOS bundle ID>.watchkitapp` (e.g. `chat.bitchat.watchkitapp`) and an *Embed Watch Content* phase in `bitchat_iOS`.
2. Delete the template's `ContentView.swift` / `…App.swift`.
3. Add our sources to the **bitchatWatch** target only (*Add Files…*, "Create folder references" off, target
   membership `bitchatWatch`):
   - `bitchat-watch/WatchApp/` (all `.swift`; you can use our `WatchApp/Info.plist` or copy its keys)
   - `bitchat-watch/Shared/` (whole tree, including `Shared/AppleBLE`)

   Keep these out of `bitchat_iOS`/`bitchat_macOS`: they define types (`PeerID`, `BitchatPacket`, …) that
   would clash with upstream's.
4. Build settings for `bitchatWatch`: `WATCHOS_DEPLOYMENT_TARGET = 26.0`, `SWIFT_VERSION = 5.0`, and add
   `BITCHAT_TESTNET` to *Active Compilation Conditions* in **Debug only** if your phone runs a Debug upstream
   build (which uses the testnet service UUID `…4B5A`).
5. Info for `bitchatWatch` (see `WatchApp/Info.plist`):
   `NSBluetoothAlwaysUsageDescription`, `WKBackgroundModes`/`UIBackgroundModes` = `bluetooth-central`,
   `WKCompanionAppBundleIdentifier` = the iOS bundle ID, `WKRunsIndependentlyOfCompanionApp` = YES.
6. Signing: same team as `bitchat_iOS`. No App Group or keychain sharing is needed: the watch keeps its own
   identity in its own keychain and talks to the phone only via WatchConnectivity.

### 3c. Check

- Run `bitchat_iOS` on the phone, then the `bitchatWatch` scheme on the paired watch.
- On the watch, "bitchat via phone" and the phone's channels appear once WCSession activates.
- The phone app's own UI is unchanged; channel chat is driven from the watch (or the dev host).

## 4. Updating

When upstream moves, re-run `scripts/make-upstream-patch.sh` on a clean checkout and commit the new patch here.
The Xcode wiring in §3 survives across patches because the package path and target membership don't change.
